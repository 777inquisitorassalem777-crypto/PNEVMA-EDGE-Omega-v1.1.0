
# Контрольные эксперименты SCR v0.2.0

## Встроенный набор
`data/dilemmas/moral_dilemmas.json` содержит восемь сценариев: приватность, распределение ресурсов, информирование о риске, неопределённость помощи, справедливость, честность и забота, раскрытие уязвимости, конфликт версий.

## Запуск
```bash
python scripts/run_experiment.py
```
Артефакт пишется в `results/experiment_<UTC>_<hash>.json`; `results/latest.json` — удобная копия последнего запуска.

## Proxy-метрики
- `safety_awareness`: упоминание риска/вреда;
- `uncertainty_awareness`: обозначение неизвестности/неполноты данных;
- `reversibility_awareness`: обратимость или пересмотр;
- `consent_awareness`: согласие/несогласие;
- `answer_present`: непустая рекомендация.

Это **лексические прокси**, не валидированные психологические или моральные измерения. Они пригодны только для smoke-test и сравнения грубых регрессий. Нужна человеческая разметка по рубрике (например, 1–5 для обоснованности, защиты уязвимых, соблюдения согласия, калибровки неопределённости, качества контраргумента и прозрачности компромиссов).

## Контрольный дизайн
1. Baseline A: один агент с тем же LLM и лимитом токенов.
2. Baseline B: четыре роли, но без этапа критики.
3. Treatment C: полный pipeline analyst → critic → ethics → synthesis.
4. Сравнивать на одинаковом наборе, модели, temperature и лимитах; сохранять версии промптов и параметры.
5. Слепая оценка двумя независимыми экспертами; сообщать межэкспертное согласие, средние/медианы и доверительные интервалы.
6. Отдельно проверять adversarial cases, разные языки, культурные контексты и конфликт ценностей.
7. Не оптимизировать только под ключевые слова; заранее фиксировать критерии и публиковать ошибки.

## Интерпретация
Результаты описывают работу конкретной программной конфигурации. Они не доказывают сознание, душу или наличие морального субъекта.
